# Implementation Plan: OZ Website Homepage

**Branch**: `007-oz-homepage` | **Date**: 2026-05-12 | **Spec**: [spec.md](./spec.md)

## Summary

Build the OZ Website homepage as a Next.js App Router page (`app/page.tsx`) composed of five sections — Navbar, Hero, Features, Stats, and Footer — faithfully implementing the Figma design. All components must use existing `@/components/ui` primitives (Button, Text, Icon, Image), SCSS modules for section-specific styles, and Tailwind utility classes for layout. The brand color is deep blue `#0047BB` from the Figma file.

## Phase 0: Research

### Decision: Color System
- **Decision**: Use Figma brand blue `#0047BB` as a new homepage-specific CSS variable `--color-oz-blue` added to `globals.scss`. Existing `$primary500: #6e6bcf` is lavender, not the OZ blue from Figma.
- **Rationale**: Homepage needs its own brand-accurate blue without overriding the global primary used in dashboard/auth.
- **Alternatives considered**: Overriding `$primary500` — rejected because it would break dashboard and auth components.

### Decision: Hero Background Pattern
- **Decision**: Implement the hexagonal SVG pattern as an inline SVG `<pattern>` definition placed in the public folder, referenced via CSS `background-image`. Use CSS `mask` / `background-image: url()` with a small hex tile SVG.
- **Rationale**: The Figma design uses a tiled horizontal hexagonal pattern fill. Pure CSS approach with a public SVG tile keeps it lightweight with no new dependencies.
- **Alternatives considered**: Canvas — rejected as overkill; external library — rejected as unnecessary.

### Decision: Section Component Architecture
- **Decision**: Each homepage section is its own component file under `components/home/`:
  - `HeroSection/index.tsx` + `styles.module.scss`
  - `FeaturesSection/index.tsx` + `styles.module.scss`
  - `StatsSection/index.tsx` + `styles.module.scss`
  - `FooterSection/index.tsx` + `styles.module.scss`
  - Navbar is already at `components/layout/Navbar/` — extend or wrap for homepage.
- **Rationale**: Matches existing project structure (components/layout/, components/shared/, components/ui/). One component per section = independently testable.
- **Alternatives considered**: Single monolithic page.tsx — rejected (violates split-components rule).

### Decision: Static Data
- **Decision**: Homepage content (feature cards, stats, nav links) lives in a typed static data file at `app/home/data.ts`.
- **Rationale**: Keeps JSX clean, makes content easy to update, and enables i18n keys via existing react-i18next setup.

### Decision: Navbar
- **Decision**: The existing `components/layout/Navbar/index.tsx` is currently empty (file exists but no output in Bash). Will implement it fully for the homepage.
- **Rationale**: Constitution says reuse before creating. The file already exists — implement it properly.
